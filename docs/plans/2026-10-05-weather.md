Plan consolidé du 5 octobre 2026. Maquette : canevas « Intégration météo » (web : détail de sortie,
cartes et états ; mobile : détail de sortie, écran « Météo du parcours »).

mêmes briques — d'où des noms de schémas génériques dès maintenant (§4).

## 2. Backend — données et cache (`fr.pedalons.…weather`)

### Points interrogés
- **Départ** : `ride.start.geometry`, sinon `ride.route.start`, sinon `route.start` du premier groupe
  avec une route non supprimée. Aucun : `NO_LOCATION`.
- **Parcours** (route du groupe, sinon de la sortie) : échantillons sur `GpxTrack.trackPoints`
  (distance cumulée exacte, altitude) tous les 15 km (`pedalons.weather.sample-step-km`) + l'arrivée ;
  un échantillon à moins de 5 km de l'arrivée est omis (92 km → 0, 15, 30, 45, 60, 75, 92). Plusieurs
  traces : chaînées dans l'ordre des ids, distance continue. Chaque échantillon garde les relèvements
  des segments jusqu'au suivant (vent relatif segment par segment).
- Échantillons en cache Caffeine `weather-route-samples` (clé = ids de traces triés — les traces sont
  remplacées, jamais modifiées, `RouteService` l.~383), dans un bean dédié `RouteSampleLookup`
  (`@CacheResult` est un intercepteur, cf. `NominatimLookup`).

### Cellule de cache
- Clé `(lat_idx, lon_idx, ele_band)` : `round(lat/0.05)`, `round(lon/0.05)`, `round(ele/100)*100`
  (NULL au départ, altitude inconnue). Constante de code. La requête Open-Meteo part du **centre de la
  maille** (mutualisation ; le lieu de rendez-vous ne sort jamais à mieux que ~3 km) avec `elevation=`
  quand connue (descente d'échelle en montagne).

### Stockage — `V61__weather_cache.sql` (tables nouvelles seulement : rolling-safe)
- `weather_cells` (entité `WeatherCell`, `@Id @Tsid`) : `lat_idx`, `lon_idx`, `ele_band` null,
  `latitude`, `longitude`, `grid_elevation` null, `timezone` null, `fetched_at` null,
  `next_refresh_at`, `nearest_need_at` null, `last_demand_at`, `claimed_until` null, `attempts`,
  `last_error` null, `created_at`, `updated_at`. Index unique `(lat_idx, lon_idx, ele_band) nulls not
  distinct`, index `(next_refresh_at)`.
- `weather_hourly` (`@IdClass`, PK `(cell_id, time)`, fk cascade) : `temperature`,
  `apparent_temperature`, `precipitation_probability` null, `precipitation`, `weather_code`,
  `wind_speed`, `wind_direction`, `wind_gusts`.
- `weather_daily` (PK `(cell_id, date)`) : `sunrise`, `sunset`.
- Upserts natifs (`on conflict do update`). Les entités doivent exister (les tests construisent le
  schéma depuis les entités). Vérifier le numéro de migration libre au moment d'écrire.

### Rafraîchissement
- **Planificateur** `WeatherPlanner` (`@Scheduled(every="5m", concurrentExecution=SKIP)`), sans HTTP,
  déterministe donc idempotent : sorties PUBLISHED non supprimées dans `[now, now+7j]` (la fenêtre affichée : une sortie partie est
  `OUT_OF_RANGE` à la lecture) → cellules
  nécessaires avec le passage le plus proche ; upsert `last_demand_at`, `nearest_need_at`,
  `next_refresh_at`.
- **TTL** (`WeatherRefreshPolicy`, fonction pure) : passage > 48 h → 6 h ; 24–48 h → 3 h ; < 24 h → 1 h.
- **Récupération** `WeatherFetchWorker` (`every="1m"`, SKIP) : claim `for update skip locked` +
  bail `claimed_until` en `QuarkusTransaction.requiringNew()` (modèle
  `NotificationEventRepository` / `NotificationDispatchService`), lots de 100 lieux par requête,
  backoff en base `min(5m·2^attempts, 1h)` (429 : heure pleine suivante), coupe-circuit en mémoire
  (ouvert 10 min après 3 échecs ou un 429), budgets `pedalons.weather.daily-call-budget` (jour UTC),
  `hourly-call-budget` et `per-minute-call-budget` (heure et minute glissantes, sous les 5 000/h et
  600/min de l'offre gratuite). Le claim ne prend que les cellules demandées par un passage du
  planificateur depuis moins de 20 min et dont le passage est encore à venir : une cellule orpheline
  (sortie partie, supprimée, annulée, déplacée) n'est plus jamais récupérée, seulement purgée. Le
  client REST d'Open-Meteo a `disable-default-mapper=true`, et la passerelle relit de toute façon une
  `WebApplicationException` comme la réponse qu'elle porte (sinon un 429 passerait pour un échec
  ordinaire).
  Jamais de suppression sur échec : on sert le cache périmé (`STALE`).
- **Purge** `WeatherHousekeeping` (cron nocturne) : heures < now − 1 j, cellules sans demande depuis 2 j.

### Client Open-Meteo (`fr.pedalons.infrastructure.openmeteo`)
- REST client MicroProfile `configKey="open-meteo"`, `User-Agent` comme `NominatimClient`, retour
  `JsonNode` (un lieu = objet, plusieurs = tableau dans l'ordre ; longueur vérifiée). Paramètres :
  `hourly=temperature_2m,apparent_temperature,precipitation_probability,precipitation,weather_code,wind_speed_10m,wind_direction_10m,wind_gusts_10m`,
  `daily=sunrise,sunset`, `timezone=auto`, `timeformat=unixtime`, `forecast_days=8`,
  `wind_speed_unit=kmh`, `models=best_match`, `cell_selection=land`, `apikey` seulement si configurée.
  Timeouts 3 s / 15 s. Ne jamais logger l'URL complète (clé). `pedalons.weather.enabled`
  (`%test` : false ; le scheduler est déjà coupé en test).

### Calculs (`RideWeatherCalculator`, fonctions pures)
- Passage = départ du groupe + distance / vitesse ; météo de l'heure la plus proche.
- Vent relatif d'un segment : composante de face moyenne pondérée par la longueur des sous-segments ;
  `HEAD` si > +0,5·v, `TAIL` si < −0,5·v, `CROSS` sinon ; `headwind` signé (km/h, + = contre).
  `relativeWindAngle` = direction **vers** laquelle souffle le vent relativement au sens de marche,
  horaire, 0 = dos, 180 = face (flèche dessinée vers l'avant puis tournée de cet angle).
- `rainAlert` : premier checkpoint où la probabilité ≥ 50 %. `windExposure` : totaux en mètres.
  `prevailingWind` : moyenne circulaire.
- Rose des vents 8 points (`CompassPoint`, direction **d'où** vient le vent). Code WMO →
  `WeatherCondition` (table dans la description du schéma).

### Lecture
- `RideWeatherService.forRide(Ride)` : détail, nombre de requêtes indépendant du nombre de groupes.
- `RideWeatherLookup.forRides(Collection<Ride>)` → `RideWeatherSummaries` (modèle `CommentCounts`) :
  0 requête si aucune sortie dans la fenêtre, 1 sinon. Branché dans `PublicationService.list` (après
  `tagLookup`) **et** `RideService.toDto`, en paramètre obligatoire de `RideDto.fromListItem` / `from`
  (pas de surcharge). Garde : un cas dans `PublicationQueryCountTest`.

## 3. API

- `GET /api/teams/{teamSlug}/rides/{rideSlug}/weather` (`getRideWeather`, tag Rides), `@PermitAll` +
  `@CheckAccess(RIDE, READ)` comme `getRide` : 404 si la sortie n'est pas lisible, **toujours 200**
  sinon, l'état dans `status`. `Cache-Control: private, no-cache` + `ETag` (version de la sortie +
  `fetchedAt`) ; `no-store` pour `UNAVAILABLE`.
- `WeatherStatus` : `OK`, `STALE` (affiché, signalé), `NOT_YET_AVAILABLE` (+ `availableFrom`),
  `UNAVAILABLE` (dans la fenêtre mais rien en cache / fournisseur en échec → « Réessayer »),
  `NO_LOCATION` (message aux organisateurs seulement), `OUT_OF_RANGE` (terminée → rien). Valeur
  inconnue côté client → rien.
- `RideDto.weather` : `RideWeatherSummaryDto`, présent seulement pour `OK`, `STALE`,
  `NOT_YET_AVAILABLE`.

## 4. Schémas (Jackson `NON_NULL` : facultatif = hors `required`)

Enums : `WeatherStatus`, `WeatherCondition` (CLEAR, MOSTLY_CLEAR, PARTLY_CLOUDY, OVERCAST, FOG,
DRIZZLE, RAIN, HEAVY_RAIN, FREEZING_RAIN, SHOWERS, SNOW, THUNDERSTORM), `RelativeWind` (HEAD, CROSS,
TAIL), `CompassPoint` (N…NW), `WeatherCheckpointKind` (START, EN_ROUTE, FINISH).

- `WindDto` { speed, gusts?, direction, compass } — km/h, degrés d'où vient le vent.
- `WeatherConditionsDto` { time, weatherCode, condition, daylight, temperature, apparentTemperature,
  precipitationProbability?, precipitation, wind } — °C, %, mm.
- `DepartureWeatherDto` { status, conditions?, sunrise?, sunset?, fetchedAt? }.
- `WeatherCheckpointDto` { index, kind, distance, elevation?, time, weather?, relativeWind?,
  headwind?, relativeWindAngle? } — **pas de coordonnées**.
- `WindSegmentDto` { fromDistance, toDistance, relativeWind, headwind }.
- `WindExposureDto` { head, cross, tail } (mètres).
- `WeatherRainAlertDto` { probability, time, distance?, condition }.
- `WeatherLegDto` (générique : un groupe de sortie aujourd'hui, une étape de voyage demain)
  { groupId?, status, startTime, averageSpeed, speedIsDefault, distance, arrivalTime, fetchedAt?,
  checkpoints, segments, windExposure, prevailingWind?, rainAlert? }.
- `WeatherAttributionDto` { name, url }.
- `RideWeatherDto` { status, availableFrom?, fetchedAt? (le plus ancien), departure, legs,
  attribution }.
- `RideWeatherSummaryDto` { status, availableFrom?, weatherCode?, condition?, daylight?,
  temperature?, temperatureMin?, temperatureMax?, maxPrecipitationProbability?, wind?, rainAlert? }.
